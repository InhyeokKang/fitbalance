# 서버를 계속 켜 두는 법

앱은 혼자 못 돈다. 진단 계산·강좌 추천·지역 검색이 전부 서버에 있어서,
서버가 꺼져 있으면 "검색하지 못했습니다. 서버 연결을 확인해 주세요"가 뜬다.

지금까지는 노트북에서 켜 두고 에뮬레이터가 `10.0.2.2:8000` 으로 붙는 구조였다.
노트북을 끄면 앱도 멈춘다. 아래 두 가지 중 상황에 맞는 쪽을 쓰면 된다.

---

## 정리부터

| | 노트북에서 켜기 | 무료 호스팅(Render) |
| --- | --- | --- |
| 준비 | 없음 | GitHub 푸시 + 계정 |
| 켜는 데 | 즉시 | 첫 요청 때 **50초** (잠들어 있으면) |
| 노트북 꺼도 | ✗ | ○ |
| 팀원 폰에서 | ✗ (같은 와이파이면 가능) | ○ |
| 비용 | 없음 | 없음 |

**8/21 시연은 노트북으로 하는 걸 권한다.** 무료 호스팅은 15분 놀면 잠들고
깨우는 데 50초가 걸린다. 심사위원 앞에서 그 50초는 길다.

**무료 호스팅은 이럴 때 쓴다** — 팀원이 각자 자기 폰에 앱을 깔아 보고 싶을 때,
노트북 없이 아무 데서나 확인하고 싶을 때.

---

## 1. 노트북에서 켜기 (지금 방식)

```bash
python -m uvicorn server.main:app --host 0.0.0.0 --port 8000
```

또는 원터치 실행 파일을 쓴다. 서버를 켜고 브라우저까지 열어 준다.

- 윈도우: `실행_윈도우.bat`
- 맥: `실행_맥.command`

**끄지 말 것.** 이 창을 닫으면 앱의 검색·진단·추천이 전부 멈춘다.

같은 와이파이에 있는 폰에서 쓰려면 노트북 IP를 확인해
`local.properties` 에 넣고 다시 빌드한다.

```
BASE_URL_DEBUG=http://192.168.0.15:8000/
```

주소는 실행 파일이 켜질 때 화면에 찍어 준다.

> 평문 HTTP는 **디버그 빌드에서만** 열려 있다
> (`app/src/main/res/xml/network_security_config.xml` 의 `debug-overrides`).
> 릴리스 빌드는 HTTPS만 받으므로 노트북 서버에 붙일 수 없다. 릴리스로 시연하려면
> 아래 Render 배포가 필요하다.

## 2. Render 무료 배포 (상시 운영)

저장소에 `render.yaml` 이 들어 있어 설정 입력 없이 배포된다.

### 준비 — 이미 돼 있다

저장소는 https://github.com/InhyeokKang/fitbalance 에 올라가 있고
`render.yaml` 도 들어 있다. 인증키는 이력 전체를 검색해도 나오지 않는다.
따로 준비할 것이 없다.

### 배포 (5분)

1. https://render.com 에서 **GitHub 계정으로 로그인**
   (Render 가 저장소를 읽어야 하므로 GitHub 로그인을 쓰는 편이 간단하다)
2. **New +** > **Blueprint**
3. `InhyeokKang/fitbalance` 를 고른다. `render.yaml` 을 읽어 설정 입력 없이 만든다
4. **Apply** 를 누르면 빌드가 시작된다. 3~5분 걸린다
5. 끝나면 `https://fitbalance-api-xxxx.onrender.com` 형태의 주소가 나온다

주소가 나오면 확인한다.

```bash
curl https://fitbalance-api-xxxx.onrender.com/api/v1/health
```

`{"status":"ok","norms_rows":450,...}` 가 나오면 된 것이다.

### 앱이 그 주소를 보게 하기

`local.properties` 에 추가하고 다시 빌드한다.

```
BASE_URL_RELEASE=https://fitbalance-api-xxxx.onrender.com/
```

릴리스 빌드가 이 주소를 쓴다. 디버그 빌드는 계속 노트북(`10.0.2.2`)을 본다.
디버그도 서버를 보게 하려면 `BASE_URL_DEBUG` 도 같은 값으로 바꾸면 된다.

> HTTPS라 `network_security_config` 를 손댈 필요가 없다.

### 알아 둘 것

- **15분 놀면 잠든다.** 다음 요청이 깨우는 데 50초쯤 걸린다.
  시연 직전에 브라우저로 `/api/v1/health` 를 한 번 열어 깨워 두면 된다.
- **진단 기록은 재배포 때 사라진다.** 무료 플랜에 디스크가 없어서다.
  서버가 뜰 때 `data/*.csv` 를 읽어 SQLite를 새로 만든다. 앱은 최근 진단을
  기기에 들고 있으므로 화면은 그대로다.
- **데이터를 바꾸면 다시 푸시하면 된다.** `data/*.csv` 가 저장소에 있어야
  서버가 읽는다. 푸시하면 Render 가 알아서 다시 배포한다.
- **속도 제한이 걸려 있다.** IP 하나당 1분에 60번이다. 넘으면 429 를 준다.
  사람이 쓰는 속도로는 걸리지 않는다. 헬스체크(`/api/v1/health`)는 제외된다.
  값은 `server/main.py` 의 `RATE_LIMIT` 에 있다.
- **웹 데모도 같이 열린다.** `https://<주소>/demo` 로 브라우저에서 바로 써 볼 수
  있다. 앱을 깔지 않고 보여 줄 때 쓴다.

## 안 될 때

**앱에 "서버 연결을 확인해 주세요"**
서버가 꺼져 있다. 노트북 방식이면 실행 창이 살아 있는지, Render면
`/api/v1/health` 가 열리는지 본다(잠들어 있으면 50초 기다린다).

**Render 배포가 실패한다**
로그에서 `pip install` 단계를 본다. `server/requirements.txt` 가
저장소에 있어야 한다.

**서버는 뜨는데 강좌가 0건**
`data/courses.csv` 가 저장소에 올라갔는지 확인한다. `.gitignore` 는
`data/raw/` 와 `data/app.db` 만 막는다. 나머지 CSV는 올라가야 한다.
