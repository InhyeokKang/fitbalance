# 실데이터 대조 결과 (2026-08-15 조사)

지금까지의 데이터 계약(`CLAUDE.md`의 CSV 스키마)은 **프롬프트 가이드에 적혀 있던 것을
그대로 따른 것**이고, 실제 공공데이터와 대조한 적이 없었다. 이 문서는 대조 결과다.

**결론: 구조는 대체로 맞으나 측정항목 구성이 틀렸다. 앱 수정이 필요하다.**

---

## 1. 국민체력100 — 무엇이 실제로 제공되는가

### 제공 형태

| 항목 | 내용 |
| --- | --- |
| 데이터셋 | 서울올림픽기념국민체육진흥공단_국민체력100 체력인증센터 측정결과 정보 |
| 링크 | https://www.data.go.kr/data/15108938/openapi.do |
| 형태 | **REST API (JSON/XML)** — 파일 다운로드가 아님 |
| 인증 | 공공데이터포털 회원가입 + **활용신청 필요**, 무료 |
| 내용 | **개인별 측정 원자료** (연령, 신장, 체중, 악력, 윗몸말아올리기 등) |

### 여기서 나온 첫 번째 사실

**공단이 백분위 기준표를 그대로 주지는 않는다.** 주는 것은 개인별 측정 레코드다.
따라서 `norms.csv`(성별×나이대×항목별 백분위표)는 **원자료에서 우리가 직접 만들어야 하는
파생 산출물**이 맞다. 최서영 트랙의 작업 정의는 이 점에서 타당하다.

`norms.csv`의 열 구성(gender, age_band, item, percentile, value) 자체는
"우리가 만들 표"의 형식이므로 공공데이터와 열 이름이 같을 필요가 없다. **이 부분은 문제없다.**

## 2. 측정항목이 틀렸다 — 가장 큰 문제

국민체력100 **성인기(만 19~64세)** 인증 측정항목은 다음 7개다.
(출처: https://nfa.kspo.or.kr/reserve/0/selectMeasureGradeItemListByAgeSe.kspo)

| 체력요인 | 측정 항목 | 단위 | 우리 앱 |
| --- | --- | --- | --- |
| 심폐지구력 | 20m 왕복오래달리기 | 회 | ✅ `shuttle_run` |
| 심폐지구력 | 트레드밀 / 스텝검사 | ml/kg/min | (대체 항목) |
| 근력 | 상대악력 | % | ✅ `grip` |
| 근지구력 | 교차윗몸일으키기 | 회 | ✅ `sit_up` |
| 유연성 | 앉아윗몸앞으로굽히기 | cm | ✅ `sit_reach` |
| **민첩성** | **10m 왕복달리기** | 초 | ❌ **없음** |
| **순발력** | **제자리멀리뛰기** | cm | ❌ **없음** |

### 문제 1 — 눈감고외발서기는 성인기 항목이 아니다

우리 앱은 `one_leg_stand`(눈감고외발서기)로 **평형성**을 진단한다.
그런데 평형성은 성인기 인증항목에 없다. **어르신기(65세 이상)** 의 운동체력 항목이다.
어르신기는 평형성·협응력을 8자 보행, 3m 표적 돌아오기 등으로 측정한다.

즉 **2040 직장인 대상 서비스에서 평형성을 측정항목으로 쓰면, 대조할 공공 기준표 자체가
존재하지 않는다.** 실데이터가 도착해도 이 항목만 채울 수 없다.

### 문제 2 — 우리 4요인 구성이 공단 분류와 다르다

| 구분 | 우리 앱 | 국민체력100 성인기 |
| --- | --- | --- |
| 1 | 근력 | 근력 (상대악력) |
| 2 | 유연성 | 유연성 (앉아윗몸앞으로굽히기) |
| 3 | 심폐지구력 | 심폐지구력 (왕복오래달리기) |
| 4 | **평형성** | **근지구력 / 민첩성 / 순발력** |

우리는 `sit_up`(교차윗몸일으키기)을 "근력"에 넣었는데, 공단 분류에서 이건 **근지구력**이다.
심사에서 "국민체력100 기반"이라고 주장하려면 요인 분류를 공단과 맞추는 편이 안전하다.

### 문제 3 — 연령 구간이 다르다

공단 인증기준은 **5세 단위**(19~24, 25~29, 30~34 ...)로 나뉜다.
우리는 10세 단위(`20s`/`30s`/`40s`/`50s`)다. 10세로 묶으면 기준이 뭉개진다.

## 3. 공공체육시설 강좌 데이터

### 시설 정보는 표준데이터가 있다

| 항목 | 내용 |
| --- | --- |
| 데이터셋 | 전국공공시설개방정보표준데이터 |
| 링크 | https://www.data.go.kr/data/15013117/standard.do |
| 형태 | 파일(CSV) + API |

제공 컬럼에 **개방시설명, 개방시설유형구분, 소재지도로명주소, 위도, 경도,
평일운영시작/종료시각, 주말운영시작/종료시각, 사용료, 관리기관명, 홈페이지주소** 가 있다.

우리 `courses.csv`의 `facility` / `lat` / `lng` / `address` 는 여기서 그대로 채울 수 있다.
**별도로 만든 `facility_addresses.csv`는 사실 이 표준데이터의 도로명주소 컬럼으로 대체 가능하다.**

### 그런데 "강좌"는 전국 통합 데이터가 없다

표준데이터가 주는 것은 **시설의 운영시간**이지 **강좌 시간표**가 아니다.
강좌(프로그램) 정보는 지자체·시설별로 따로 공개되고, 전국을 한 번에 받는 표준 데이터셋이 없다.

즉 `courses.csv`의 `title` / `weekday` / `start_time` / `sport` 는
**지자체별 데이터를 모으거나 시설 홈페이지에서 수집해야 한다.** 최서영 트랙의 작업이 맞다.

## 4. 그래서 무엇을 고쳐야 하는가

### 반드시 고쳐야 할 것

1. **`one_leg_stand`(평형성)를 성인기 항목으로 교체**
   대안 A: 제자리멀리뛰기(`standing_jump`, 순발력)
   대안 B: 10m 왕복달리기(`shuttle_10m`, 민첩성)
   → 둘 다 넣어 6항목으로 가거나, 하나만 골라 5항목 유지

2. **요인 분류를 공단 기준에 맞춤**
   `sit_up`을 근력 → **근지구력**으로 이동

3. **나이대 구간을 5세 단위로**
   `age_band` 값을 `20-24`, `25-29`, ... 형태로. 열 이름은 그대로 두면 코드 변경 최소화

### 검토가 필요한 것

4. `facility_addresses.csv`를 유지할지, 표준데이터의 주소 컬럼을 `courses.csv`에 넣을지
   → `courses.csv` 스키마 변경이 필요하므로 강인혁 판단

5. 심폐지구력 대체 항목(트레드밀/스텝검사)을 지원할지
   → 사용자가 직접 측정하기 어려우므로 왕복오래달리기만 두는 편이 현실적

## 5. 데이터 확보 절차 (강인혁 / 최서영)

1. 공공데이터포털 회원가입 → **활용신청** (즉시 승인되는 경우가 많음)
   https://www.data.go.kr/data/15108938/openapi.do
2. 인증키 발급 후 API로 측정 원자료 수집
3. 원자료에서 성별·연령대·항목별 백분위 산출 → `norms.csv`
4. 전국공공시설개방정보표준데이터에서 수도권 체육시설 추출 → `courses.csv`의 시설·좌표·주소
5. 각 시설 홈페이지·지자체 데이터에서 강좌 시간표 수집 → `title`/`weekday`/`start_time`/`sport`
6. 강좌별 체력요인 태그 부여

> **주의**: 활용신청 시 "활용목적"에 공모전 참가를 명시할 것.
> API 응답에 성별 컬럼이 포함되는지 반드시 확인할 것. 없으면 성별 구분 기준표를 만들 수 없어
> 진단 로직 자체를 바꿔야 한다.
