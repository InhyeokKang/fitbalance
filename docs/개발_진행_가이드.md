# Claude Code 프롬프트 가이드 (로컬 개발용)

붙여넣기 순서: ① 레포 루트에 CLAUDE.md 저장 → ② 첨부 문서(아이디어 템플릿)를 프로젝트 폴더에 docs/로 넣기 → ③ 1단계 프롬프트부터 순서대로.

---

## 0. 레포 루트에 둘 CLAUDE.md (그대로 저장)

```markdown
# 프로젝트: 직장인 신체 불균형 진단 + 공공 체육 강좌 추천 앱

## 문서
- 서비스 정의·기능·데이터는 docs/ 폴더의 문서가 유일한 기준. 코드 작성 전 반드시 읽을 것.
- docs와 이 파일이 충돌하면 이 파일이 우선.

## 스택 (변경 금지)
- 앱: Kotlin + Jetpack Compose, 단일 모듈, minSdk 26
- 백엔드: Python FastAPI + SQLite, 파일 하나로 시작해 필요 시 분리
- 지도: 카카오맵 Android SDK (키는 local.properties에서 읽기, 코드에 하드코딩 금지)

## 스코프 — 이번 빌드에서 만들지 않는 것
- 로그인/회원가입 없음. 사용자 식별은 기기 로컬 UUID
- 추천은 콘텐츠 기반 코사인 유사도만. 협업 필터링/행렬분해 금지
- 예약은 외부 브라우저 링크로 연결. 예약 연동 구현 금지
- B2G 대시보드는 정적 화면 1장만
- 위 항목을 "확장하면 좋다"는 제안도 하지 말 것

## 데이터 계약 (외부에서 도착 예정, 스키마 고정)
- data/norms.csv: gender, age_band, item, percentile, value
  → 성별·나이대·측정항목별 백분위 기준표. 지금은 샘플 20행을 직접 생성해 개발하고,
    실데이터 도착 시 파일 교체만으로 동작해야 함
- data/courses.csv: course_id, title, facility, lat, lng, weekday, start_time, sport,
  tag_strength, tag_flex, tag_cardio, tag_balance (태그는 0/1)
  → 동일하게 샘플 30행으로 개발
- CSV 스키마를 코드 사정에 맞춰 바꾸지 말 것. 문제가 있으면 바꾸는 대신 보고할 것.

## 검증 (작업 완료 선언 전 필수)
- 백엔드: uvicorn 구동 후 각 엔드포인트 curl 호출 결과를 보여줄 것. pytest 최소 스모크 테스트 유지
- 앱: .\gradlew.bat assembleDebug 성공까지 확인. 에뮬레이터 화면은 내가 직접 확인하고
  문제는 logcat을 붙여넣어 전달하겠음
- 빌드 실패 상태로 턴을 끝내지 말 것

## 작업 방식
- 한 턴에 한 단계만. 다음 단계로 임의로 넘어가지 말 것
- 파일을 새로 만들거나 구조를 바꾸기 전에 무엇을 왜 바꾸는지 한 줄로 먼저 말할 것
- 주석·문자열은 한국어
```

## 1단계 — 설계 확정 (plan mode로: 구현 전 계획만 받기)

```text
docs/ 아래 문서를 전부 읽어라. 구현하지 말고 다음 두 가지만 산출해라.

1. 화면 목록: 화면별 이름, 목적, 표시 요소, 이동 관계. 7개 이내.
2. API 명세: 엔드포인트, 메서드, 요청/응답 JSON 예시.
   진단(측정값 입력→백분위·약점 판정), 추천(약점→강좌 랭킹), 강좌 조회 3개가 핵심.

CLAUDE.md의 스코프 제외 항목이 화면·API에 섞여 있지 않은지 스스로 검수한 결과도 붙여라.
이 산출물은 contracts/design.md 로 저장해라. 내가 승인하기 전까지 코드 작성 금지.
```

→ 여기서 나온 design.md를 직접 읽고 이상한 부분을 고친 뒤 "승인, 2단계 진행"이라고 말하면 됨. **이 검토가 전체에서 가장 남는 장사임** (백엔드·앱이 전부 이 문서를 따라가므로).

## 2단계 — 백엔드 (샘플 데이터 포함)

```text
contracts/design.md 명세대로 FastAPI 백엔드를 구현해라.
- CLAUDE.md의 CSV 스키마대로 data/norms.csv 샘플 20행, data/courses.csv 샘플 30행을 만들어 사용
- 서버 기동 시 CSV를 SQLite로 적재
- 완료 기준: uvicorn 구동 → 3개 엔드포인트 curl 실행 결과 제시, pytest 통과
```

## 3단계 — 앱 화면 (백엔드 연결 전, 명세 기반)

```text
design.md의 화면 목록대로 Compose 화면을 구현해라.
- 이 단계에서는 서버 호출 없이 design.md의 응답 JSON 예시를 그대로 가짜 응답으로 사용
- 화면 이동 전부 연결, 입력 폼은 검증 포함(숫자 범위는 docs의 측정항목 기준)
- 완료 기준: .\gradlew.bat assembleDebug 성공
```

## 4단계 — 연결

```text
가짜 응답을 Retrofit 실호출로 교체해라. 서버 주소는 BuildConfig로 분리(로컬/배포).
로딩·실패 상태 화면 포함. 완료 기준: assembleDebug 성공 + 에뮬레이터에서 내가 시나리오 확인.
```

## 5단계 이후 — 버그 반영 턴 (매일 반복)

```text
아래는 오늘 버그 리포트다. 심각도 '막힘'부터 순서대로 고쳐라.
한 건 고칠 때마다 원인 한 줄 + 수정 파일을 보고하고, 전부 끝나면 assembleDebug로 확인해라.
[시트 내용 붙여넣기]
```

## 자주 겪는 상황 대응

- **Claude Code는 에뮬레이터 화면을 못 본다** → UI 문제는 말로 설명하지 말고 `adb logcat` 에러 부분이나 스크린샷 설명 + 재현 절차를 붙여넣는 게 몇 배 빠름
- **크래시 났을 때**: `문제: [화면]에서 [행동] 시 종료. logcat: [붙여넣기]. 원인 추정 말고 스택트레이스 기준으로 고쳐라.`
- **한 턴이 너무 커져서 산으로 갈 때**: 되돌리려 하지 말고 git으로 마지막 정상 커밋으로 리셋 후 더 작게 다시 지시. 그래서 **단계 완료마다 커밋**을 습관화할 것 (커밋도 시켜도 됨: "지금 상태를 의미 있는 단위로 커밋해라")
- **서영님 실데이터 도착 시**: `data/*.csv를 교체했다. 스키마 검증 스크립트를 돌리고, 실데이터 기준으로 진단 결과 3건을 뽑아 보여라.`

## 하루 압축 진행 시 (오늘 데모 완성 목표)
- 1단계(설계 승인)는 압축해도 생략하지 말 것 — 검토 15분이 이후 재작업 몇 시간을 막음
- 2·3단계는 프롬프트 하나로 합쳐도 됨: "design.md대로 백엔드와 앱 화면을 순서대로 구현하되, 백엔드 curl 확인을 끝낸 뒤 앱으로 넘어가라"
- 대신 **커밋 지점은 유지**(백엔드 완료 시점, 앱 빌드 성공 시점 각각) — 하루에 몰수록 리셋 지점이 생명
- 지도 화면은 오늘 범위에서 제외하고 4단계 연결까지를 데모 완성선으로 잡을 것

## 에뮬레이터에서 한글 입력이 안 될 때

기본 에뮬레이터는 영어만 설정돼 있어 **한글 자판이 없다.** 이 앱은 집·직장 지역을
한글로 검색하므로 자판이 없으면 시연을 못 한다. 한 번만 해 두면 된다.

```bash
python tools/emulator_korean.py
```

시스템 언어에 한국어를 넣고 프레임워크를 재시작한다(1분 남짓). 끝나면 입력창을 눌렀을 때
자판 아래에 **지구본 키**가 생기고, 그걸 누르면 영문 ↔ 한글이 바뀐다.

> Play 스토어 이미지(`google_apis_playstore`)는 `adb root` 가 막혀 있어 이 스크립트가
> 실패한다. 그때는 에뮬레이터에서 직접 **설정 > 시스템 > 언어 및 입력 > 언어** 에
> 한국어를 추가하면 된다.

한글 자판 없이도 앱은 쓸 수 있다. 검색창 아래 **시·도별 목록**을 눌러 고르면 된다.
다만 동 단위까지 좁히려면 검색이 필요하다.

> 개발 중에 한글을 넣어 확인만 하고 싶다면, 호스트 클립보드에 복사한 뒤
> `adb shell input keyevent 279` (붙여넣기)로도 된다. 에뮬레이터가 호스트 클립보드를
> 공유한다. `adb shell input text` 는 비ASCII를 못 보낸다.

## 카카오 지도를 에뮬레이터에서 확인하는 법

기본 x86_64 에뮬레이터에서는 카카오 지도가 **뜨지 않는다.** SDK가 ARM 라이브러리만
담고 있어서다. 실기기(모든 안드로이드 폰)는 ARM이라 문제가 없지만, 폰 없이 확인하려면
아래 네 가지를 모두 맞춰야 한다. 하나라도 빠지면 회색 화면이거나 간이 지도로 넘어간다.

**1) ARM 변환이 되는 시스템 이미지**

```
sdkmanager "system-images;android-30;google_apis;x86_64"
avdmanager create avd -n fitbalance_arm -k "system-images;android-30;google_apis;x86_64" -d pixel_6
```

확인: `adb shell getprop ro.dalvik.vm.isa.arm64` 가 `x86_64` 를 돌려주면 변환이 켜진 것.

**2) OpenGL ES 3 활성화**

카카오 지도는 ES3가 필요한데 에뮬레이터 기본값이 ES2다. `~/.android/advancedFeatures.ini`에:

```
GLESDynamicVersion = on
```

에뮬레이터는 `-gpu host` 로 띄운다. 확인: logcat에 `ANDROID_EMU_gles_max_version_3`.
`no ES 3 support` 가 보이면 이 설정이 안 먹은 것.

**3) DNS**

기본 부팅 시 DNS가 비어 있어 `dapi.kakao.com` 해석이 실패한다.

```
emulator -avd fitbalance_arm -gpu host -dns-server 8.8.8.8,1.1.1.1
```

**4) ARM으로 설치**

APK에 x86_64 라이브러리(AndroidX)와 ARM 라이브러리(카카오)가 섞여 있어, 그냥 설치하면
x86_64 프로세스로 떠서 카카오 라이브러리를 못 읽는다.

```
adb install --abi arm64-v8a -r app/build/outputs/apk/debug/app-debug.apk
```

확인: `adb shell "dumpsys package com.fitbalance.app | grep primaryCpuAbi"` 가 `arm64-v8a`.

### 인증 문제 구분법

지도가 안 뜰 때 앱을 다시 돌리지 말고 아래로 먼저 확인한다. 즉시 사유가 나온다.

```
curl -s -H "Authorization: KakaoAK <네이티브앱키>" \
     -H "KA: mapSdk/2.12.8 os/android-30 lang/ko-KR origin/<키해시> android_pkg/com.fitbalance.app" \
     https://dapi.kakao.com/v2/maps/vector/auth
```

- `200` (본문 없음) → 정상
- `keyhash mismatched` → 콘솔에 등록한 키 해시가 다름
- `disabled OPEN_MAP_AND_LOCAL service` → 콘솔에서 카카오맵 제품이 꺼져 있음

디버그 키 해시 구하기:

```
keytool -exportcert -alias androiddebugkey -keystore ~/.android/debug.keystore \
  -storepass android -keypass android | openssl sha1 -binary | openssl base64
```

릴리스 빌드(8/21 서명 빌드)에서는 **릴리스 키스토어의 키 해시를 따로 등록**해야 한다.
